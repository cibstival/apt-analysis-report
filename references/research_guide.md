# 조사 가이드 (섹션별 검색어·출처 기준)

## 목차
1. 공통 원칙
2. 시장 데이터(market.json)
3. 단지 기본정보·시세
4. 에피소드(과거 이상 구간) 분석
5. 지역 심층 분석
6. 전망·드라이버·손익 모델 파라미터

---
## 1. 공통 원칙
- 최신성이 중요한 항목(금리, 규제, 시세, 주간 동향)은 매 실행마다 검색한다. 기억에 의존하지 않는다.
- 출처 우선순위: 정부·공공기관(한국은행, 국토부, 정책브리핑, 서울시) > 한국부동산원·KB 통계 > 주요 언론 > 단지 정보 플랫폼 > 블로그(블로그는 교차확인 후 '참고'로만).
- 기사 인용은 요약 + "(매체 YYYY.M.D)". 긴 원문 복사 금지.
- 수치 성격을 기록: 실거래/호가/시세/추정, 공급면적/전용면적, 조합원분양가/일반분양가, 기준 시점.

## 2. 시장 데이터
| 항목 | 검색 예시 | 반영 위치 |
|---|---|---|
| 한국 기준금리 결정 | "한국은행 기준금리 결정 YYYY년 M월", 한국은행 통화정책방향 | rates.kr |
| 미국 FOMC | "FOMC federal funds rate decision <Month YYYY>", federalreserve.gov 성명 | rates.us (상단) |
| 서울 구별 평단가 | "KB 3.3㎡당 평균 매매가격 강남구 노원구 YYYY", KB 데이터허브 월간 ㎡당 평균매매가 ×3.3 | groups.*.ppp, anchors |
| 구별 변동률 | "한국부동산원 주간 아파트가격 누적 상승률 자치구 YYYY" | 보간 근거, sources_rows |
| 거래량 | "서울 아파트 매매 거래량 월 서울부동산정보광장", 자치구별 거래량 | volume.rows |

## 3. 단지 기본정보·시세
- 검색: "<단지명> 세대수 입주 용적률", "<단지명> 실거래가", "<단지명> KB시세", "<단지명> 전세", K-apt(공동주택관리정보시스템), 아파트위키, 리치고, 호갱노노, 네이버부동산.
- 확인할 것: 평형별 공급/전용면적·세대수, 동 수·최고층, 주차대수, 교통(역 거리), 학군, 정비사업(재건축 안전진단·조합 단계).
- 시세는 날짜를 함께 기록(`kb_asof`, private_price.label).
- 실거래가 공개 페이지에만 있을 때는 목록을 CSV로 옮기고 trades_note에 출처·기준일.

## 4. 에피소드 분석
1. `metrics.py`의 `halves`와 market 금리를 비교해 후보 구간을 고른다: 금리↑인데 거래↑, 금리↓인데 거래↓, 반기 거래 0건, 개별 최고가 대비 -15% 이상 거래.
2. 검색: "<지역> 아파트 거래량 YYYY년 상반기 원인", "<정책명> 출시 효과", "주담대 금리 YYYY년 M월", "<구> 아파트값 YYYY 하락/상승 이유", "<동> 개발 YYYY".
3. factors는 요인·시기·기사요지(출처)·단지 함의 4칸, 5~6개. 금리(기준 vs 시장), 정책금융, 규제, 가격조정, 지역 호재, 역풍을 골고루 점검.
4. trade_events는 해당 연도 각 거래일에 가까운 사건을 한 줄로.

## 5. 지역 심층 분석
- 검색: "<동> 재개발 재건축 YYYY", "<동> 신속통합기획", "<구역명> 정비계획 분양가 비례율", "<동> 교통 호재 GTX 역", "<구> 입주물량 YYYY", "<동> 도시재생".
- timeline: 지정·해제·확정·인가 등 행정 단계 날짜 순.
- pipeline: 사업별 규모·단계·단지와의 거리/관계. 분양가를 쓸 땐 성격(조합원/일반)과 추정 시점 필수.
- structure: 수요(직주·학군), 공급(입주 시기), 가격 앵커, 물리적 제약(지형·문화재·경관), 산업·인구.
- outlook: 단기(~1년)/중기(3~5년)/장기(입주기) 3행.

## 6. 전망·드라이버·손익 모델
| 파라미터 | 검색 예시 |
|---|---|
| 주담대 금리(model.rate) | "5대 은행 주담대 5년 고정형 금리 YYYY년 M월", "은행채 5년물 금리" |
| LTV·한도(model.ltv/loan_cap) | "<지역> 규제지역 LTV 무주택 YYYY", "주담대 한도 15억 이하" |
| 토지거래허가·실거주 의무 | "<구/동> 토지거래허가구역 지정 YYYY" |
| 세제 | "YYYY 세제개편안 종부세 양도세 1주택" |
| 예금금리(deposit_rate) | "5대 은행 1년 정기예금 금리 YYYY년 M월" |
| 보유세(holding_tax) | "<단지명> 공시가격" → 재산세 추정(모르면 추정치로 명시) |
| 주간 동향(drivers 수요 이동) | "한국부동산원 주간 아파트 가격 동향 <구> YYYY년 M월" |

시나리오 확률·변동률은 근거(과거 최대 낙폭 `focus_max_drawdown`, 금리 경로, 개발 일정)를 전제 칸에 적고 '주관 가정'임을 유지한다.

## 7. 정책 점검 (`check_policy.py`가 재확인 필요를 낼 때)
`config/policy.json`의 항목별로 아래를 검색해 **바뀐 것만** 고친다. 확인 후 반드시 `check_policy.py --touch`로 기록한다.

| policy.json 항목 | 검색 예시 | 바뀌면 고칠 곳 |
|---|---|---|
| `acquisition_tax` | "취득세율 1주택 YYYY", "지방세법 제11조 개정", "취득세 6억 9억 구간 개편" | `low_upto/high_from/low_rate/high_rate`, `effective_from`, `source` |
| `brokerage` | "중개보수 상한요율 개정 YYYY", "공인중개사법 시행규칙 별표 1" | `brackets[]`, `vat_ratio` |
| `capital_gains` | "1세대 1주택 양도세 비과세 기준 12억 YYYY", "양도세 개정 시행" | `assumption`, `report_note` |
| `loan` | "주담대 LTV 규제지역 YYYY년 M월", "주담대 한도 6억 유지", "스트레스 DSR 3단계 가산금리" | `current{}`, `ltv_default/loan_cap_default` |
| `regulation` | "규제지역 조정대상지역 지정 해제 YYYY", "토지거래허가구역 연장 해제 서울" | `current{}` |
| `tax_reform` | "세제개편안 국회 통과 종부세 양도세 YYYY", "세법 개정안 시행일" | `current{}`, `status`(입법 예정→시행), `effective_from` |

원칙
- 출처는 정책브리핑(korea.kr)·국토부·기재부·행안부·국세청·법제처(law.go.kr) > 주요 언론. 블로그·커뮤니티는 근거로 쓰지 않는다.
- "발표"와 "시행"을 구분한다. 시행 전이면 `status`에 "입법 예정"을 남기고 값은 바꾸지 않는다.
- 값을 바꿀 때 `changelog`에 날짜·내용·출처를 남긴다(`--touch --note --source`가 자동으로 추가).
- 세율·요율의 **구조**(예: 구간 수)가 바뀌어 JSON으로 표현이 안 되면 `lib_report.py`의 `acquisition_tax_rate/brokerage_rate`와 `_formula` 짝을 함께 고치고, `python scripts/build_report.py`로 예시 단지를 다시 빌드해 수식이 깨지지 않는지 확인한다.
